# 后台故障恢复验证（2026-09-12）

## 修复与范围

- 本地存储被浏览器策略禁用时，主题、编辑模式和保存跳转仍可工作。UI 偏好临时保存在内存中；文章恢复副本失败会明确提示，编辑器卸载时不再产生未处理的存储错误。
- 媒体上传设置 60 秒超时。超时、连接中断、服务端错误或无法解析成功响应时标记结果不确定，队列继续处理后续图片。新增刷新媒体库按钮，保留队列并重新读取图片；结果不确定的重试需要用户核对确认，避免直接重复发送。
- Vercel 忽略构建脚本使用上次部署基线比较整个后台目录。多提交推送和合并提交不会因为最后一个提交只改博客内容而误跳过构建；基线缺失或检查失败时执行构建。

仅修改 `admin/`。检查期间远端 main 新增留言板提交 `32694b6ed565cadcdd5d5bb0357a4b3e56e57a33`，已合入该更新；相对此基线的 `source/` 树保持 `f3d6656f672e0a74b1d2bcd411d4f1907d3f6807`。

## 本地验证

- `npm run lint`、`npm run typecheck`、`npm test`、`npm run build`。
- `npm run smoke:quality`：分页、筛选、复制草稿、保存并读取正文、七个后台页面、390px 手机导航；浏览器错误为空。
- `npm run smoke:resilience`：同时禁止 localStorage、sessionStorage、IndexedDB，确认页面、双向主题切换、编辑模式切换、新建草稿保存与跳转、API 正文读回、离开编辑器均正常；恢复副本失败提示可见，浏览器错误为空。
- 上传故障测试让首张图片写入本地 Mock 后丢弃响应，使用原生 XHR 超时，断言产品设置为 60000ms，仅测试时加速至 1500ms。第二张成功，刷新后第一张可见且队列保留，取消重试后 POST 数仍为 2，图片数量不变。
- Git 构建判断测试使用真实临时仓库，覆盖纯内容改动、多提交后台改动、合并提交、缺失基线和 Git 失败。

故障测试只操作经过身份和配置校验的本机 Mock；未向真实文章或图片库写入测试数据。浏览器登录生产账号后的真实写入链路不在这次故障测试范围内。生产部署结果另以 PR、CI、Vercel 对应提交状态和上线后的健康检查确认。

## 使用边界

存储被禁用时，内存中的主题偏好不能跨刷新保存；文章恢复副本不可用时需要及时远程保存。上传超时不会取消服务器已经执行的写入，因此结果不确定时必须先核对媒体库；本次没有引入服务端上传幂等协议。
